# Frozen policy input interface v1

This describes policy INPUT only. Resolver OUTPUT is a separate structure: output disposition strings are NOT values of input enums. All objects below reject unknown keys. Every listed field is required unless explicitly optional. Numbers named id are positive integers; booleans are actual JSON booleans; arrays have no duplicate identities. References are nonempty HTTPS GitHub decision URLs. Strings are nonempty unless stated otherwise.

Prepublication v1 amendment: a role may include optional `member_selector`, exactly `members` (default) or `team_managers`. The latter selects only directly observed team maintainers, never inherited or parent managers. It is prohibited on exception roles. Empty selections remain non-routable/vacant. This implements the owner's explicit routing decision; it is not an inference of operational authority. Consumers must use the amended validator before accepting this optional field. Specialty lead is the separate ordered next stage. No older parser has been deployed by this work.

Root fields:
- schema_version: integer literal 1.
- organization: {login: GitHub organization login string, id: positive integer}.
- freshness: {max_age_seconds: positive integer or null, proposed_max_age_seconds: positive integer or null}. Only max_age_seconds is accepted policy. If null, cached operations require an explicit positive caller threshold. Proposed value NEVER defaults any operation.
- owner_fallback: {id: positive user integer ID, login: display login string, decision_refs: nonempty reference array}. Lookup verifies stable ID, and changed login is reported as drift, not a replacement identity.
- repositories: nonempty array of unique repository records below.
- coordination_roles: array of {name: string, team_id: positive integer, state: accepted|pending_acceptance, decision_refs: nonempty reference array}. These are informational sidecars, never chain levels or inferred operational acceptance.

Repository record fields:
- id: positive repository integer ID; full_name: organization/name string; public: boolean (false means never include in public directory).
- anchor_team_id: positive integer or null; managed_by_team_ids: array of positive integers; management_state: accepted|unresolved; management_decision_refs: reference array. Accepted management requires nonempty IDs/references; unresolved requires empty IDs. These fields describe explicit governance records, not inferred individual team managers.
- roles: exactly three records in order: repository_team, repository_maintainer, repository_lead_maintainer. Each is {level: one of those three strings, state: accepted|proposed|unresolved|exception, team_ids: array of positive integers, decision_refs: reference array}. Accepted requires nonempty team IDs and references; proposed requires nonempty concrete candidate IDs (references may be empty); unresolved requires empty IDs; exception requires empty IDs and repository exception provenance. Only accepted role mappings can yield eligible recipients. Proposed/unresolved/exception still appear in output with their disposition. Repository-team accepted ID must equal anchor. No inferred role from access or team manager status.
- parent_chain: {mode: live_ancestors|none, expected_team_ids: array of positive integers in nearest-to-farthest order, decision_refs: nonempty reference array}. Anchor is ONLY the repository-level anchor_team_id. live_ancestors requires a nonnull anchor. none requires null anchor, empty expected IDs and a documented owner/private exception. Parent changes are drift, not new policy.
- expected_grants: null OR array of {team_id: positive integer, permission: pull|triage|push|maintain|admin, basis: accepted_baseline|observed_baseline, decision_refs: reference array}. Null means no expectation declared; [] means expect zero grants. A nonempty array specifies the expected complete team-grant set. Comparisons are read-only and distinguish baseline provenance; they authorize no changes.
- exceptions: array of {code: owner_controlled|private_accepted|unbootstrapped, reason: string, decision_refs: nonempty reference array}. Null anchor requires owner_controlled or private_accepted. Education has real repository ID, nonnull known anchor, and unbootstrapped exception. Exception codes become output dispositions; no extra disposition field occurs in INPUT.
- path_overrides: array of {prefix: normalized relative directory prefix ending '/', state: accepted|proposed|unresolved, decision_refs: reference array, roles: nonempty unique subset of role records}. Reject absolute paths, backslashes, traversal, glob syntax and duplicate prefixes. Longest matching prefix wins. Only maintainer/lead levels may be overridden in v1; repository-team anchor/parent chain cannot change. Accepted override requires decision references. Matched nonaccepted overrides yield unresolved/proposed role output rather than falling through. Initial policy uses [] everywhere because no path override is accepted.

Output conventions (not input schema): parent_chain.mode=none produces a `not_applicable_no_anchor` output disposition before owner fallback. The input exception code unbootstrapped produces an `unbootstrapped` output disposition for an existing but empty repository. Public output contains only public team/repository links, no logins, IDs of private repos, rosters, or raw access details. Private output may resolve current people, but does not confer accepted individual responsibility. No delivery or membership mutation happens from output.

Starting exceptions: .github uses exception role state at all three levels with owner_controlled provenance; internal-discussion uses exception role state at all three levels with private_accepted provenance. Their anchors are null and parent mode none. Every other unresolved role is exactly state unresolved with []. Education is not treated as an unknown repository.

Snapshot and CLI structure may be implemented within this policy contract; it does not add fields to policy INPUT. Required behavior remains transactional full collection, last-success retention, failure sidecar, explicit cache freshness, direct/inherited membership separation, REST GET and fixed GraphQL read queries only, deterministic public directory, complete coverage and regression tests.
